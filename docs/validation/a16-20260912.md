## Measured small-circuit latency

Three repeats, median wall seconds per 1,000 ms simulated time, after 100 ms
warmup. Execution includes input handling, readout and GPU synchronization.
Loading/compilation is separate in the JSON.

| Model | CPU | CUDA |
|---|---:|---:|
| Artificial toy, 12 cells | 0.02760 s | 2.55773 s |
| MaleCNS escape, 313 cells | 0.10838 s | 2.63954 s |

**CUDA is slower on these small circuits.** This reference path uploads currents
and synchronizes an error flag on each tick. A fractional virtual GPU also has
scheduling overhead. These data do not establish whole-brain scaling, speedup,
or full-card A16 performance. Keep CPU as the default. Device-resident multi-tick
schedules and batching are the next optimization target, with the same
conformance gate retained.

The first device attempt failed at NVRTC compilation because `math.h` was not
provided by the pip CUDA environment. Removing that unnecessary host header
allowed NVRTC's built-in device math to compile. The complete gate then passed;
CPU-only tests could not detect this deployment issue.

## External readout learning

`examples/train_reflex.py --backend cuda` ran a reward-trained two-choice action
readout using the unchanged 313-neuron circuit. On 80 balanced held-out trials,
accuracy rose from **50% to 100%** after 24 batches over 64 training trials.
Runtime was 33.87 seconds. CPU independently reproduced the same accuracy.

Only three external readout weights were trained. This is a simple, resetting
left/right obstacle task with varied stimulus strength and distractors, not
biological plasticity or broad game skill. See the [experiment guide](../../examples/REFLEX_TRAINING.md).
